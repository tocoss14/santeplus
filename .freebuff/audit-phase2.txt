1. OBJECTIF PRINCIPAL

L'objectif n'est plus simplement de vérifier que :

          « les tests passent ».

L'objectif est de vérifier que :

          le comportement réel de SantéPlus respecte effectivement le fonctionnement
          métier défini dans les présentations et spécifications existantes.

Tu dois notamment déterminer si les fonctionnalités sont :

        · réellement implémentées ;
        · réellement connectées ;
        · réellement persistées ;
        · réellement calculées ;
        · réellement exécutées de bout en bout ;
        · protégées côté backend ;
        · cohérentes entre UI, API, base de données et journal financier ;
        · réellement fonctionnelles et non simplement simulées/mockées.

2. RÈGLE ABSOLUE : NE PAS MODIFIER LE CODE
AU DÉBUT

IMPORTANT

Pendant la première partie de cette Phase 2 :

NE CORRIGE PAS LE CODE.

Tu dois d'abord :

      1. inspecter ;
      2. comprendre ;
      3. tester ;
      4. reproduire ;
      5. documenter ;
      6. identifier les anomalies ;
      7. mesurer leur gravité.
Aucune modification fonctionnelle ne doit être réalisée avant d'avoir produit les résultats de l'audit.

        · scripts de test ;
