FONCTIONNELLE ET TECHNIQUE

SantéPlus Bénin -- Comparaison des 3 présentations avec la
plateforme réellement développée

Tu interviens sur le projet SantéPlus Bénin.

Les Phases 1, 2 et 3 ont déjà été réalisées. La Phase 2 a notamment identifié plusieurs anomalies
critiques et la Phase 3 a été consacrée à leur correction et à leur validation.

OBJECTIF DE CETTE PHASE

Cette Phase 4 a un objectif précis :

          Vérifier que la plateforme SantéPlus réellement développée correspond fidèlement
          à ce qui est présenté et promis dans les trois documents officiels de présentation du
          projet.

Il ne s'agit PAS encore d'une refonte UX, d'une optimisation de performance ou d'un audit de sécurité
complet.

Il s'agit d'un audit de conformité entre le produit spécifié et le produit réellement implémenté.

2. RÈGLE ABSOLUE DE L'AUDIT

Tu dois comparer :

DOCUMENTS DE RÉFÉRENCE  CODE  BASE DE DONNÉES  API  INTERFACE  WORKFLOW
RÉEL  TESTS

Ne considère jamais qu'une fonctionnalité existe simplement parce que :

        · une page existe ;
        · un bouton existe ;
        · une route API existe ;
        · un modèle de données existe ;
        · un commentaire dans le code dit qu'elle existe ;
        · une fonction porte le bon nom.
Une fonctionnalité ne sera considérée comme réellement conforme que si son fonctionnement est
démontrable.

10. AUDIT DU CTS

Vérifie réellement :

        · PRIME ;
        · FEES ;
        · BUDGET ;
        · ENGAGEMENT ;
        · CONSUMPTION ;
        · CANCELLATION ;
        · REFUND ;
        · CALL_FOR_FUNDS ;
        · PAYMENT ;
        · RENEWAL_CREDIT ;
        · STOP_LOSS ;
        · ADJUSTMENT.
Vérifie également :

Formule

Frais de gestion = Prime encaissée × taux de gestion

Budget santé

Budget = Prime encaissée - frais de gestion

Disponible

Disponible = Budget - consommations - engagements

Résultat technique provisoire

Résultat = Prime - frais - consommations - engagements

Les engagements doivent être pris en compte.
